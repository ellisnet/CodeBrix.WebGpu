================================================================================
wgpu-native-tools - how the codebrix_wgpu native libraries are built
================================================================================

WHAT IS BUILT
--------------------------------------------------------------------------------
ONE native library per runtime identifier, `codebrix_wgpu`
(libcodebrix_wgpu.so / codebrix_wgpu.dll / libcodebrix_wgpu.dylib), which
CodeBrix.WebGpu.Native P/Invokes. It is the cdylib of OUR crate codebrix-wgpu/,
which links wgpu-native (wgpu 29.0.3 via wgpu-native v29.0.1.1) and exports:

  (a) every function of webgpu.h  } wgpu-native's own 228 #[no_mangle] functions,
  (b) every function of wgpu.h    } re-exported from its rlib (see patches/)
  (c) the 15 wgpuCodebrix* functions of specs/codebrix.yml - codebrix-wgpu/src/
      codebrix.rs, C header codebrix-wgpu/include/codebrix_wgpu.h:
      api version + build info + struct layouts (wgpuCodebrixGetStructLayout:
      sizeof/alignof of every one of the 123 structs of the three headers, the
      managed binding's load-time safety net; table generated by
      tools-scripts/gen-layouts.sh), the device's backend, the Vulkan / D3D12
      objects behind a device or texture, wrapping an application's VkImage /
      ID3D12Resource / MTLTexture as a WGPUTexture, adopting an application's
      VkDevice / MTLDevice as a WGPUAdapter + WGPUDevice, and an explicit
      texture state transition.

Nothing else is exported (no Rust std / crate symbol); every gate checks the
exact set against specs/expected-exports.txt (243 functions; written by the
binding generator from the three YAMLs). The export set is identical on all
nine RIDs: a function for a backend the platform lacks returns
WGPUStatus_Error / NULL.

KNOWN LIMITS OF wgpu 29.0.3 (documented in codebrix.rs; FIXLIST 2026-10-11)
  * wgpuCodebrixInstanceAdoptD3d12Device ALWAYS returns WGPUStatus_Error:
    wgpu-hal's dx12 backend has no public way to wrap an EXISTING ID3D12Device
    (Adapter::expose is pub(super), no device_from_raw). Use a wgpu-created
    device + wgpuCodebrixDeviceGetD3d12Info instead.
  * `initialState` of the CreateTextureFrom* functions: wgpu-core registers
    every texture created from hal as UNINITIALIZED and offers no way to declare
    another state; Undefined is exact, anything else is logged and treated as
    Undefined (wgpu's first use transitions from UNDEFINED).
  * wgpuCodebrixCommandEncoderTransitionTexture validates the texture's usage
    against the target state itself; wgpu-core checks the rest at Finish.
  * The Metal and D3D12 paths compile only on their own platforms: they are
    written against wgpu-hal 29.0.3's sources but are UNCOMPILED until Jeremy's
    first macOS / Windows run (the smoke test exercises each of them).

HOW codebrix-wgpu LINKS wgpu-native (and why there are two patches)
--------------------------------------------------------------------------------
The approach of the plan WON for the exports and needed one addition:
  * patches/0001 turns wgpu-native into an rlib; codebrix-wgpu depends on it by
    path (`wgpu-native = { path = "../wgpu-native" }`) and `pub use
    wgpu_native::*;`. rustc exports the #[no_mangle] functions of a linked rlib
    from a cdylib - PROVEN by nm on every RID (all 228 present, nothing else).
    The #[path]-module fallback was not needed.
  * patches/0002 adds ONE module line to wgpu-native's lib.rs so our
    bridge/bridge.rs compiles as a child of its crate root: the handle structs'
    fields are private, and only a child module can read them or build new
    handles (patches/README.txt has the details).
Both patches are applied to a SCRATCH copy (wgpu-native/ + codebrix-wgpu/
side by side) by every script; the vendored tree is never built in place.

THE RULE: NOTHING BUT CRATES.IO IS FETCHED AT BUILD TIME
--------------------------------------------------------------------------------
  * wgpu-native/ is the unmodified release archive with webgpu-headers at the
    pinned submodule commit (UPSTREAM.txt); the archives are in
    upstream-downloads/. Never edit that tree: changes go in patches/.
  * crates.io crates are "NuGet packages for Rust" (ruling of 2026-10-11):
    codebrix-wgpu/Cargo.lock pins every one (version + checksum); every build
    passes --locked; `cargo update` is never run - a lock change is a recorded
    upstream bump (refresh-upstream.sh). The lock is wgpu-native's own plus our
    package (cargo pruned 5 unused entries; no version differs).
  * Linux: `cargo fetch` is the one network step (CodeBrix.RustTools.Docker,
    into a cargo cache volume); the SHIPPED compile runs with --network none.
    The derived image installs its tools (clang/lld via dnf, Rust via rustup)
    once, at image build time (the 2026-08-28 ruling).
  * Tools on a build machine (podman, the NDK, rustup + the pinned toolchain,
    LLVM/libclang, Visual Studio, Xcode CLT) are prerequisites the scripts
    check for and NAME when missing; they never install them.

HOW TO REBUILD
--------------------------------------------------------------------------------
  cd wgpu-native-tools/linux   && ./build.sh            # all three Linux RIDs
  cd wgpu-native-tools/android && DEVICE_ARM64=<serial> DEVICE_X64=<serial> ./build.sh
  cd wgpu-native-tools\windows ; .\build-win-x64.ps1 ; .\build-win-arm64.ps1
  cd wgpu-native-tools/macos   && ./build-osx-arm64.sh && ./build-osx-x64.sh
  cd wgpu-native-tools         && ./build-host.sh       # dev-box .so for the tests

Every script: copies wgpu-native/ + codebrix-wgpu/ to scratch (patches applied
there), builds the release cdylib (fat LTO; WGPU_NATIVE_VERSION from
linux/pins.env, which wgpuGetVersion() reports), keeps an unstripped twin
(debug info; zlib-compressed on ELF; .pdb / .dSYM elsewhere), strips, writes
LICENSE-WgpuNative.txt beside the binary, runs THE GATE (architecture, exact
exports, system-only dependencies - never libvulkan/libGL/vulkan-1.dll at link
time, wgpu loads them at run time -, glibc floor / 16 KB alignment / deployment
target / static CRT as the platform needs, licence file, the smoke test against
the STAGED file, and reproducibility: Linux always (the RustTools.Docker twin),
Android / Windows / macOS on request), writes output/<rid>/BUILD-INFO.txt and -
only when the gate passed - ADOPTS the result into
../src/CodeBrix.WebGpu.Native/runtimes/<rid>/native/ (+ the twin into
unstripped/<rid>/). ADOPT=0 (bash) / -NoAdopt (PowerShell) skips that. Then
update that RID's block in BUILD-PROVENANCE.txt from BUILD-INFO.txt, and
refresh output/SHA256SUMS + unstripped/SHA256SUMS (linux/build.sh writes both).

CodeBrix.RustTools (dog-fooded through driver/, see driver/README.txt):
  * Linux: RustTools.Docker runs the image, container, source copy, `cargo
    fetch`, the in-container licence audit and a full build (the twin); the
    shipped compile is plain `podman run --network none` because RustTools.Docker
    cannot switch a container's network off. Linux x64/arm64/riscv64 use the
    x86_64 image; arm64 and riscv64 CROSS-compile against the sysroot of their
    own pinned manylinux image (linux/export-sysroot.sh), ~70 s each, and are
    gated in that image under qemu. Containerfile.aarch64 / .riscv64 are the
    documented native-under-qemu fallback (unbuilt, unused).
  * Android: RustWorkbench.BuildAndroidAsync + AndroidLinkProfile (API 33).
  * Licences: the RustTools licence audit (licenses/compose-license-wgpunative.sh
    --refresh).

THE SMOKE TEST
--------------------------------------------------------------------------------
smoke-test.c loads the library BY PATH (dlopen / LoadLibrary, as .NET does),
resolves every entry point it uses and every symbol of specs/expected-exports.txt
by name, then checks: wgpuCodebrixGetApiVersion == 1; wgpuGetVersion ==
29.0.1.1 packed; wgpuCodebrixGetBuildInfo; struct layouts (15 structs, C sizeof
/ alignof == the native's) and an unknown name -> Error; instance +
wgpuInstanceEnumerateAdapters; request adapter + device. With NO adapter it
prints "SKIPPED: no adapter", releases and exits 0 (22 checks). With one: a
compute pass doubling 256 u32 with readback; a render-pass clear of an RGBA8
texture + CopyTextureToBuffer + map + pixel check; DeviceGetBackend == the
adapter's; transitions ColorTarget -> ShaderResource (Success),
StorageReadWrite without storage usage and Undefined (Error); per backend -
Vulkan: GetVulkanInfo (non-null handles, extension names), TextureGetVulkanInfo
(VkFormat 37), a texture WRAPPED around that VkImage cleared to a new colour and
read back through the ORIGINAL, and AdoptVulkanDevice of the same VkDevice into
a second instance with a compute pass on it; D3D12: the same with
GetD3d12Info / ID3D12Resource, AdoptD3d12Device -> Error; Metal: the same with
wgpu.h's Metal getters and AdoptMetalDevice; every OTHER backend's functions
return Error / NULL; no uncaptured device errors; everything released and
wgpuGenerateReport shows 0 live objects (47 checks). "SMOKE TEST PASSED", exit 0.

THE LICENCE FILE (identical on all nine RIDs)
--------------------------------------------------------------------------------
  LICENSE-WgpuNative.txt = licenses/LICENSE-WgpuNative.txt, composed ONCE from
  Cargo.lock by licenses/compose-license-wgpunative.sh:
    PART 1  wgpu-native LICENSE.MIT (it is "MIT OR Apache-2.0"; used under MIT)
    PART 2  webgpu-headers LICENSE (BSD-3-Clause)
    PART 3  the 82 crates.io crates that LINK INTO the library on any RID (normal
            dependency edges; build scripts and proc-macros never link), each
            under the licence it is used with (MIT where offered; else
            Apache-2.0, Zlib, ISC, BSD-3-Clause, Unicode-3.0, CC0-1.0 - all
            permissive), with the licence files each crate PUBLISHES, verbatim
            (licenses/crates/<name>-<version>/; identical texts printed once).
            A crate that publishes no licence file gets its Cargo.toml authors as
            the copyright line under the standard text (licenses/texts/).
  --refresh re-runs the CodeBrix.RustTools licence audit (LicensePolicy
  .Permissive(), per target triple) and STOPS on any linked crate that is not
  permissive or not resolvable. --check (run by every bash build, and inside
  the Linux gate) proves the file is current AND that every crates.io package
  of Cargo.lock is either listed or recorded in licenses/crates/not-linked.txt.
  licenses/** is -text in .gitattributes (two crates publish CRLF files, kept
  verbatim). THIRD-PARTY-NOTICES.txt at the repository root mirrors it.

BUMPING WGPU (the exact recipe)
--------------------------------------------------------------------------------
  1. ./refresh-upstream.sh v<new tag>
       downloads the tag + the webgpu-headers commit it pins, records sha256s,
       FAILS if a patch no longer applies, prints the C API delta, replaces
       wgpu-native/, re-derives codebrix-wgpu/Cargo.lock (upstream lock + our
       package; aborts if our dependencies would move an upstream version),
       moves the "=" pins in codebrix-wgpu/Cargo.toml and updates linux/pins.env
       (tag, sha256s, headers commit, wgpu-core version, RUST_TOOLCHAIN from the
       new rust-toolchain.toml).
       (`--into <dir>` builds the tree elsewhere and changes nothing: the
       re-verification of the current pin.)
  2. If wgpu.h changed: update specs/wgpu.yml to match it.
  3. dotnet run --project tools/CodeBrix.WebGpu.BindingGenerator -- --write
       (the binding AND specs/expected-exports.txt)
  4. If codebrix.yml or the hal/core APIs codebrix.rs uses changed: fix
     codebrix-wgpu/src/codebrix.rs (+ bridge/bridge.rs if wgpu-native's handle
     structs changed) and bump api_version in codebrix.yml + the C header.
  5. tools-scripts/gen-layouts.sh
  6. licenses/compose-license-wgpunative.sh --refresh
  7. ./build-host.sh ; dotnet test   (the laptop loop: smoke test + managed tests)
  8. FORCE_IMAGE_REBUILD=1 linux/build.sh all     (new RUST_TOOLCHAIN -> new image)
     android/build.sh ; Windows + macOS scripts on Jeremy's machines
  9. UPSTREAM.txt, BUILD-PROVENANCE.txt, THIRD-PARTY-NOTICES.txt; commit; publish
     once all nine RIDs are in.
  No hand edits beyond 2 and 4 unless the YAML schema itself changed (then the
  generator's model is the one place to fix).
